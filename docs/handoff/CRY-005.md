# Handoff CRY-005

Strategy registry for crypto-signal-engine. Each swing strategy has a declaration: name, semantic version, lifecycle, description, parameter schema with defaults, and owner notes. `sync` copies that declaration onto `strategy_registry`. Signals and paper trades store the version that produced them.

## Summary

`analysis/strategy_catalog.py` is the catalog. The four swing strategies (`donchian`, `keltner_break`, `vol_breakout`, `ichimoku`) are version `1.0.0` and lifecycle `paper`. `validate_catalog()` checks the whole catalog. `validate_declaration()` checks one declaration: a short name, `MAJOR.MINOR.PATCH`, status in `research` / `paper` / `retired`, a description, and a schema whose defaults match `number` / `integer` / `string` / `boolean`.

`strategy_registry.status` stays the operational gate (`incubating` / `trusted` / `paused` / `retired`). The ticket's research / paper / retired value is a new column, `lifecycle`. `sync` writes the declaration on insert, on a digest change, and on an unchanged digest. An unchanged digest still leaves `live_from` and the change notes alone.

`strategies_payload(rows)` is the body `GET /integration/v1/strategies` should return. Each item has `name`, `version`, `status` (the lifecycle), `description`, `parameter_schema`, `owner_notes`, plus `spec_key`, `timeframe`, and `operational_status`.

`Repository.log_crypto_signal` stores `strategy_version`. An empty argument is filled from the catalog, so a `swing_vol_breakout` row gets `1.0.0` and a confluence row stays empty. `open_position` stamps the same version on the position. The position row and the closed trade row persist it. A restart copies it back onto the in-memory position, so the trade written later still carries it. A mirrored signal keeps the original version.

## Assumptions

- Previous ticket `jarvis/TRD-002` was already on origin at `f7dca5a`. This branch was created from `main` (`2429e2c`). The environment allowed `jarvis/CRY-005`.
- `GET /integration/v1/strategies` is on `jarvis/TRD-002` (`scheduler/integration_v1.py`), which is not in this tree. This branch does not copy that server. `strategies_payload` is the payload that route should serve.
- One declaration per strategy name. The 4h and 8h specs share version `1.0.0`.
- Schema defaults are the function defaults in `analysis/lab/strategies.py` (donchian `n=55`, keltner `k=2.0`, vol breakout `z=2.0`, ichimoku empty). The swing book's overrides stay in `owner_notes` and in the existing `params` column.
- A retired lifecycle still returns its version from `version_for`. Pausing a spec stays an operational `status` change. `TRADING` is still `incubating` and `trusted`.
- Undeclared signal types, including confluence and the 2h candidates, store an empty version.
- `1.0.0` is the first declared version of each of the four strategies.

## Known gaps

- The HTTP handler on `jarvis/TRD-002` still builds its own `/strategies` body. It starts returning these fields when that handler calls `strategies_payload`.
- `parameter_schema` defaults are JSON numbers. TRD-002's response check rejects floats outside money and decimal-string fields. Wiring the payload into that envelope needs the schema defaults left as numbers on purpose, or the check taught to allow them inside `parameter_schema`.
- Specs that are not in the catalog (2h candidates) get empty declaration columns. `apply_declaration` leaves them alone.
- SQLite tests create the columns via `create_all`. A live Postgres database picks them up from `_COLUMN_MIGRATIONS` on the next engine startup.

## Security impact

Declarations are code and rows. Nothing here places, cancels, or modifies an order. `analysis/strategy_catalog.py` imports only the standard library. No secret was added. `.env` was not read and `.env.example` was not changed.
