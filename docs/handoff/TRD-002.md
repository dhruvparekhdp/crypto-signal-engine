# Handoff TRD-002

Read-only trading-v1 API for crypto-signal-engine. A separate process serves `GET /integration/v1/*` on `127.0.0.1` by default. It reads the paper book. It does not import the order modules and it was not pointed at a live exchange.

## Summary

`python -m scheduler.integration_v1` binds `INTEGRATION_BIND`:`INTEGRATION_PORT` (default `127.0.0.1:8091`). Every GET needs `Authorization: Bearer <INTEGRATION_API_TOKEN>`. The compare is SHA-256 of both strings, then `hmac.compare_digest`. An empty token refuses every request. POST, PUT, PATCH, and DELETE return 405. Unknown GET paths return 404. The public dashboard on `0.0.0.0` does not mount these routes.

Each response is the trading-v1 envelope with `source_engine=crypto-signal-engine`, `schema_version=1.0`, `mode=paper`, and `correlation_id` copied from `X-Correlation-ID`. `is_stale` is true when the newest row for that view is older than `INTEGRATION_STALE_SECONDS` (default 900), or when the view has no rows. Stale and empty views use `status=degraded`. A database error uses HTTP 503 and `status=unavailable`, and the message does not include the exception text.

`/signals`, `/positions`, `/trades`, and `/strategies` take `limit` (default 100, above 500 is HTTP 400) and `since`. They return `data.items` and `data.next_cursor` (`<ISO-8601>|<id>`). Prices and quantities are decimal strings. Margin, fees, and P&L are `{amount, currency}` in INR. Quote prices use USDT.

## Assumptions

- This branch was created from `main` (`2429e2c`). The environment allowed `jarvis/TRD-002`. CRY-002 stays on its own branch and is not in this diff.
- The API is a separate process, not a router on the public health server, so the default bind can be loopback.
- `mode` is `paper` on every response. This process only reads the paper book. Shadow rows still appear inside `/signals` through `trade_mode`.
- Account money is INR because that is the unit stored on `paper_trades` / `paper_positions`. Quote prices are USDT.
- `/strategies` reads `strategy_registry`. When that table is empty it lists `settings.swing_strategies` and treats that config as fresh.
- `since` is ISO-8601. `next_cursor` is that timestamp plus `|` and the row id so two rows in the same microsecond both get returned.
- A non-GET is 405 before the token is checked. GET without a token is 401.
- The process does not call `init_db`, so it does not rewrite the admin password.

## Known gaps

- The columns are floats. The API quantizes the float's shortest round-trip to 8 decimal places (2 for INR). It is not a decimal column.
- `/market/overview` is the latest `crypto_snapshots` row per symbol. It is not a list endpoint and it does not include commodity snapshots.
- Flat trades (`net_pnl == 0`) are in `closed_trades` and in neither `wins` nor `losses`.
- The process is not started by `main.py`. An operator runs it beside the engine, with `INTEGRATION_API_TOKEN` set in that process only.
- Production rows were not read. Stale behaviour was checked with an in-memory clock, not the live EC2 database.

## Security impact

Fail closed: no token, wrong token, and an unset token are HTTP 401. The token is not logged. Mutating methods do not exist. The default socket is loopback. The module's import graph (`scheduler.integration_v1` and the local modules it reaches) does not import `execution`. Database failures return a fixed message.

## Rollback

Stop the integration process if it was started. Revert this branch. The engine's own server is unchanged.

```bash
git checkout main
git branch -D jarvis/TRD-002
git push origin --delete jarvis/TRD-002
```
