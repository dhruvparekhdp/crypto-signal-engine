# CRY-004 handoff — data source health

## Summary

Each data feed now has a last successful update, an error count, a last latency, and a state: fresh, degraded, stale, or erroring.

The state is logged (`source_feed` on each poll, `source_health` on the 10-minute heartbeat). `GET /integration/v1/health` returns the same snapshot. That path was not in the repo; this ticket adds it. `GET /health` is unchanged, so the liveness check still reports symbols and uptime only.

A notify hook calls the existing Telegram notifier when a feed changes state. It is off unless `source_health_notify` is true.

Tests cover a fresh feed, a stale feed, and an erroring feed, plus degraded (one error, or a slow poll), a disabled hook, and the HTTP snapshot.

## How a feed is marked

Defaults, overridable in settings:

- fresh: last success newer than 300s, no consecutive errors, last latency at most 5000 ms
- degraded: still inside that window, but at least one consecutive error, or latency above 5000 ms
- stale: no success inside 300s (a feed that has never succeeded goes stale 300s after it was first seen)
- erroring: 3 consecutive errors. An error streak wins over silence.

`error_count` is the lifetime total and stays after a later success. `consecutive_errors` resets on success.

## Assumptions

- `/integration/v1/health` did not exist. It is a new read-only GET. It is not under `/api/`, so the API rate limit does not apply, same as `/health`.
- The hook is `TelegramNotifier.send_text`. Logs stay at info or warning. `scheduler.alerts` turns error-level logs into Telegram, and this tracker must not use that path while the hook is off.
- Polls that return without an update count as errors: CoinDCX and CoinGecko when their failure counter rises, klines when zero symbols refreshed, Fear & Greed when the fetch returns None. An empty watchlist therefore records a klines error.
- Fear & Greed still replaces the cached reading with None when the fetch misses, which is what the job did before.
- The seed and the git SHA from CRY-003 are unrelated. This branch does not contain CRY-001 or CRY-003.
- A pull request is opened so the owner can review and merge later.

## Known gaps

- WebSocket feeds (Binance, Delta, Twelve Data) are not in the book. Only the polled jobs listed above record samples.
- A klines poll that refreshes nothing, including an empty watchlist, is an error.
- Thresholds are read at process start (`AppRunner.start`), not on every `/settings` save.
- Cold ruff and cold mypy on the whole tree were already red. Only the new module was linted and typechecked.
- The five paper tests above fail while the clock sits in the NFP blackout. They should pass again after 20:00 IST on 6 Nov 2026.

## Security impact

No secrets. The snapshot stores a caller-supplied `last_error` trimmed to 200 characters. The runner does not pass exception text into it. The tracker does not call an exchange and does not place, cancel, or modify orders. The notify hook is off by default and only sends a feed name, a state, an error count, a latency, and a timestamp.
