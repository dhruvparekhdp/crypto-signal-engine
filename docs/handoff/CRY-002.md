# Handoff CRY-002

Live order, cancel, and modify calls are blocked unless two process environment variables are set. Neither is set by default. Nothing live was enabled, and no exchange was contacted.

## Summary

`assert_live_trading_allowed()` in `execution/live_guard.py` is the single gate. It raises `LiveTradingDisabled` unless `LIVE_TRADING_ENABLED` is `true` (case-insensitive) and `LIVE_TRADING_CONFIRM` equals `YES_PLACE_REAL_ORDERS` exactly. Both are read from the process environment, not from `Settings` and not from `app_settings`, so `/settings` cannot turn live trading on.

Every Binance USD-M write (`prepare`, `market`, `protect`, `cancel_all`) and every Delta India write (`place_market`, `place_stop_market`, `place_take_profit_market`, `cancel_all`, `edit_stop`, `cancel_order`, `set_leverage`) calls the guard before `_request`. `LiveBook` and `DeltaBook` call the same methods only through wrappers in `execution/live_guard.py`, which assert again first. `scripts/delta_live_rehearsal.py`, `scripts/delta_stop_fill_test.py`, and `scripts/delta_testnet_flow.py` call the wrappers directly, including cleanup. `scripts/delta_testnet_adopt.py` places through `DeltaBook`, so it hits the same gate. None of these scripts were run.

`main()` logs `trading_mode` with `mode=paper/research` and `live=OFF` when the flags are absent. If both flags match, the same line reports `mode=live` and `live=ON`. The confirmation phrase is not written to the log.

Reads (balances, positions, order books, open orders, trading status) are unchanged.

## Files changed

- `execution/live_guard.py` — the guard, the startup fields, and the only module allowed to call the exchange mutation methods.
- `execution/binance_futures.py`, `execution/delta_india.py` — each mutation method asserts before HTTP.
- `execution/live_book.py`, `execution/delta_book.py` — order paths call the wrappers.
- `scripts/delta_live_rehearsal.py`, `scripts/delta_stop_fill_test.py`, `scripts/delta_testnet_flow.py` — direct mutation calls, including cleanup and the raw leverage POST, go through the wrappers.
- `main.py` — startup log line.
- `.env.example` — comments naming the two variables, left unset, without the confirmation phrase.
- `tests/conftest.py` — other tests keep their in-memory fakes; this suite does not set the flags for them.
- `tests/test_live_trading_guard.py` — raises without the flags, mock HTTP client is not called, AST scan, startup log.
- `tests/test_delta_ladder.py`, `tests/test_delta_crash_safe.py` — fake helpers so the scan does not see a mutation call outside the guard module.
- `docs/handoff/CRY-002.md` — this note.

## Assumptions

- The second variable is `LIVE_TRADING_CONFIRM` and the exact phrase is `YES_PLACE_REAL_ORDERS`. The ticket required a second confirmation and did not name it. The phrase lives in `execution/live_guard.py` and is not logged.
- `LIVE_TRADING_ENABLED` must be the word `true` after strip, any case. `1` and `yes` stay blocked.
- Branch `jarvis/CRY-002` was created from `main` (`2429e2c`). This environment allowed that branch. AUD-2 stays on `jarvis/AUD-2` and is not in this diff.
- The call scan covers every `*.py` file except `execution/live_guard.py`. Tests are included. Fake subclasses delegate through `_record_stop` / `_record_edit` so `super().place_stop_market()` is not a scanned call. The guard tests invoke client methods with `getattr` for the same reason; the real methods still assert before HTTP.
- A mutating `_request` (`POST` / `PUT` / `DELETE` to an order path) is allowed only inside `execution/binance_futures.py` and `execution/delta_india.py`, and only in a function whose first statement is the guard.
- Existing tests monkeypatch `assert_live_trading_allowed` to a no-op so in-memory fakes still record orders. `tests.test_live_trading_guard` does not get that patch, and it deletes both variables at the start of each test.
- Production `app_settings` was not read. `delta_india_mode=live` in the database is no longer enough to send an order.

## Known gaps

- An exchange position that is already open cannot be flattened, cancelled, or amended by this process until both variables are set. That includes Delta reconcile and the kill-switch close. Cancels are order paths, so they are blocked on purpose.
- `getattr(client, "place_market")` is not a syntactic call, so the AST scan does not see it. The client method still asserts first, which the runtime tests cover. A brand-new mutation that is only reached through `getattr` and forgets the guard would need a new name in `ORDER_METHODS` and a `_request` path the HTTP scan already flags.
- The test-suite no-op is process-local to pytest. It is not in `main.py`.
- Ruff and mypy remain red on `main` for the reasons in the AUD-2 handoff. This ticket did not clean them.
- The operator scripts still contain the code that would place testnet orders. Running them now raises `LiveTradingDisabled` unless both variables are present in that process. They were not run here.

## Security impact

Default process: no order, cancel, modify, leverage, or margin-type HTTP call can leave the two clients. Database flags and `live_trading_mode` do not bypass the guard. The startup line tells an operator the mode is paper/research and live is OFF.

The confirmation phrase is source, not a secret. It is omitted from `.env.example` and from the exception text so a log line does not print it.

## Rollback

Revert this branch. No schema or dependency change. After rollback, Delta orders are again possible when `delta_india_mode` is `live` and `delta_india_live_orders` is true.
