# CRY-001 — Dev setup + CI

## Summary

`make setup` creates `.venv` and installs the existing requirement files.
`make lint`, `make typecheck`, and `make test` are the local checks.
`make check` runs the three of them. `make audit` is pip-audit and
`make secrets` is gitleaks (the binary must be on `PATH`; CI installs 8.28.0).

GitHub Actions workflow `.github/workflows/ci.yml` runs those checks on every
push and pull request. The existing deploy workflow is unchanged and still
deploys only from `main`.

Tests do not read a developer `.env`, do not keep exchange API keys, force
live-trading switches off, and refuse any socket that is not loopback.
Exchange clients in tests are the fakes the suite already injects; a new test
drives Binance and Delta through a fake HTTP client and asserts no socket opens.

`.env.example` lists variable names only (commented). It has no values, so
copying it cannot blank a default or store a credential.

## Assumptions

- Branch is `jarvis/cry-001` (lowercase). The ticket id in the handoff path stays `CRY-001`.
- A pull request is opened so the owner can review. `SYSTEM_CONTEXT.md` says not to open one unless asked; this ticket says the owner reviews and merges later, and nothing is merged or deployed from here.
- `.env.example` uses commented names, not `KEY=`. An empty assignment would override pydantic defaults (`DATABASE_URL=` would replace the local SQLite default).
- Lint and typecheck compare `(file, rule)` counts to a baseline. Line-number shifts do not fail CI. A new violation of a rule a file already has fails only when the count grows. Fixing an old finding does not require a baseline edit.
- `cryptography` stays `>=43,<46`. The ignored advisories are fixed only in 46 or newer. This ticket does not upgrade dependencies.
- CI Python is 3.12, matching `.github/workflows/deploy.yml`.
- gitleaks allowlists five paths that contain published API-doc signature vectors or obvious placeholders (`tests/test_delta_india.py`, `tests/test_live_book.py`, `tests/test_finetune_pipeline.py`, `tests/test_keys_page.py`, `scripts/dev_server.sh`). The default rule set still runs everywhere else, including git history.
- pip-audit’s job contacts the public advisory database. The test job does not use the network. “Offline” here means the test process: no exchange calls and no sockets except loopback.

## Known gaps

- A cold `ruff check` and `mypy` are still red on old code (about 6000 ruff findings, a few hundred mypy errors). CI does not boil that ocean.
- The cryptography advisories above are still present in the pinned range.
- `make secrets` fails locally if `gitleaks` is not installed. CI installs 8.28.0 itself.
- The allowlisted test files would not be scanned if a real key were later pasted into them.
- `deploy.yml` still runs its own pytest job on `main` before deploy. That job now inherits the offline guard, but this ticket does not change the deploy steps.

## Security impact

- Tests cannot dial an exchange or load broker keys from `.env` or the parent environment. Live-trading mode is forced off for the test process only.
- Production still reads `.env` when `CRYPTO_ENGINE_ENV_FILE` is unset. No order path, broker client, or live-trading default was changed.
- CI’s test job is given no secrets. The workflow permission is `contents: read`.
- `.env.example` no longer contains placeholder passwords or a sample database URL.
- gitleaks scans the full history of each push and pull request. pip-audit scans both requirement files and fails on any advisory that is not in the cryptography ignore list.
