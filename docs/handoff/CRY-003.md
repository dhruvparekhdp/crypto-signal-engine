# CRY-003 handoff — report export

## Summary

`python -m scripts.export_report` writes a backtest and a signal audit to `report.json`, `report.csv`, and `report.md` in `--out`.

Each report records strategy name and version (`paper-cycle` / `1`), the paper-cycle params, the data range, the data source, the random seed, the code git SHA, and the run timestamp.

Re-running with the same candles (or the same `--synthetic` count and `--seed`), the same signal rows, the same config, and the same `--run-at` produces identical metrics. The determinism tests pass. With a fixed `--run-at` and `--git-sha`, the three files are byte-identical across two CLI runs.

The command does not place orders and does not call an exchange. Candles come from a CSV or from a local generator that uses `random.Random(seed)`. The backtest engine itself is unchanged.

## How to run it

```bash
python -m scripts.export_report --synthetic 400 --seed 7 --out data/reports/run1
python -m scripts.export_report --candles bars.csv --signals rows.json --out out/
```

`--synthetic` and `--candles` are mutually exclusive. Pass `--run-at` (ISO) when the whole file, including the timestamp, must match a previous run. Omit it and the timestamp is `now` in UTC; the metrics stay the same.

CSV columns: `ts,open,high,low,close,volume`. Signal JSON is a list, or an object with `signals` or `rows`.

## Assumptions

- One command writes all three formats. The existing `scripts/backtest_v2.py` lake CLI is a different tool and was left in place.
- Strategy identity is the constant `paper-cycle` version `1`. Bump `STRATEGY_VERSION` when the replay or audit arithmetic this export reports changes. The git SHA is separate provenance (`git rev-parse HEAD`, or `--git-sha`, or `unknown` when git is unavailable).
- The seed is stored on every report and is used only to build `--synthetic` bars. File candles are not regenerated from the seed. The engine does not draw random numbers.
- CLI config flags are `--starting-wallet` (1000), `--leverage` (10), and `--min-confidence` (0.70). Every other `CycleConfig` field stays at its default and is still written into `params`.
- Closed trades are stored under `metrics.backtest.closed_trades` so `summary()`'s `trades` aggregate (`total`, `wins`, `win_rate_pct`, and the rest) stays intact.
- Group keys are sorted so file order does not depend on dict order.
- A pull request is opened so the owner can review and merge later, same as CRY-001.

## Known gaps

- Main has no pull-request CI workflow until CRY-001 merges. `deploy.yml` runs on push to main only. This ticket's done condition is the local determinism test, which passed. This branch does not add a second CI workflow.
- Cold `ruff` and cold `mypy` on the whole tree are already red. Only the new files were linted and typechecked.
- `params` is the full `CycleConfig`, including nested fee, slippage, and review settings. A caller who changes an unexposed default changes the recorded params and can change the metrics. That is the intended record of the run.
- Signal rows that fail `audit`'s validity filter are dropped by the existing audit, then the remaining records are sorted. Invalid rows therefore do not appear in the export.

## Security impact

No secrets. No `.env` values are read or printed. No network calls, no broker or exchange clients, no order placement, cancel, or modify. The only subprocess is `git rev-parse HEAD`, with stderr discarded.
